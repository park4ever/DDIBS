# DDIBS V3 Plan

## 1. 문서 목적

이 문서는 DDIBS V3에서 무엇을 진행할지 간단하게 정리한 계획 문서다.

V1이 **핵심 플로우 완성**, V2가 **테스트 재현성 · 배치 운영성 · 관리자 주문 조회 · 테스트 구조 정리**에 집중한 단계였다면,  
V3는 그 위에 **운영 조회 완성도**, **시연 가능성**, **최소 프론트엔드 데모 레이어**를 더해  
DDIBS를 “잘 만든 백엔드”에서 “직접 보여줄 수 있는 운영형 시스템”으로 끌어올리는 단계로 정의한다.

이 문서는 Blueprint처럼 큰 기준 문서가 아니라,  
**V3에서 어디까지 진행하고 무엇을 제외할지 빠르게 합의하기 위한 실무형 메모**에 가깝다.

---

## 2. V3 목표

V3의 목표는 범용 커머스 기능을 더 많이 추가하는 것이 아니다.  
DDIBS가 이미 가진 핵심 메시지, 즉 **고수요 발매 상황에서의 정합성 · 동시성 · 상태 전이 · 운영성**을  
더 잘 보여주고, 더 쉽게 시연할 수 있게 만드는 것이 핵심이다.

정리하면 V3 목표는 아래와 같다.

1. 관리자/운영 조회 기능을 더 완성도 있게 만든다.
2. 발매/재고/정산 흐름을 운영 관점에서 보여줄 수 있게 한다.
3. 백엔드 API를 시연할 수 있는 최소 프론트엔드 데모 레이어를 도입한다.
4. 시퀀스 다이어그램과 시연 문서를 보강해 포트폴리오 설명력을 높인다.

---

## 3. V3 방향 요약

### V3에서 집중할 것
- 관리자 정산 조회/API 고도화
- 발매/재고 운영 조회 고도화
- 최소 프론트엔드 데모 레이어 추가
- 시연 문서 / 시퀀스 다이어그램 / README 보강

### V3에서 유지할 원칙
- 백엔드 중심 프로젝트라는 정체성을 유지한다.
- 프론트엔드는 DDIBS 백엔드를 보여주기 위한 **보조 레이어**로 다룬다.
- 운영자 관점의 화면을 우선한다.
- 기능 수보다 **설명 가능성**과 **시연 완성도**를 우선한다.

### V3에서 지금 하지 않을 것
- 장바구니
- 쿠폰 / 포인트
- 리뷰 / 문의
- 배송 / 송장
- 환불 / 교환
- 실제 PG 연동
- 마이크로서비스 / Kafka / K8s
- 사용자용 화려한 상점 프론트
- 과도한 통계 / 추천 / 알림 기능

즉 V3는 **일반 쇼핑몰 확장판이 아니라, 운영형 드롭 런치 시스템 시연 완성판**으로 간다.

---

## 4. In Scope

### 4.1 관리자 정산 조회/API 고도화
우선순위: 상

목표:
- 정산 상태, 판매자, 기간 기준으로 정산을 조회할 수 있게 한다.
- 관리자 관점에서 정산 흐름을 실제로 추적할 수 있게 만든다.

예상 작업:
- 정산 검색 조건 DTO 추가
- 정산 요약/상세 응답 DTO 추가
- QueryDSL 기반 정산 조회 추가
- 관리자 정산 조회 서비스/컨트롤러 보강
- 정산 조회 테스트 작성

예상 조건:
- 정산 코드
- 정산 상태
- 판매자 ID
- 기간(from / to)
- 페이징 / 정렬

---

### 4.2 발매/재고 운영 조회 고도화
우선순위: 상

목표:
- 운영자가 현재 발매 상태와 재고 상황을 실용적으로 확인할 수 있게 한다.
- DDIBS의 발매 엔진 성격을 운영 조회를 통해 더 분명하게 보여준다.

예상 작업:
- 발매 목록 조회 조건 추가
- 발매 상태 기준 조회
- 기간 기준 조회
- 판매자 / 상품 기준 조회
- LaunchVariant 재고 현황 조회
- 발매 상세 또는 운영 조회 응답 보강

예상 조건:
- Launch 상태
- 판매자 ID
- 상품명 키워드
- 기간(from / to)
- 페이징 / 정렬

---

### 4.3 최소 프론트엔드 데모 레이어
우선순위: 중

목표:
- 백엔드 API를 직접 시연할 수 있는 최소 관리자 프론트를 만든다.
- 프론트엔드는 백엔드 흐름 설명용으로 사용한다.

기술 방향:
- React
- Vite

기본 원칙:
- 사용자용 화려한 상점 UI를 만들지 않는다.
- 관리자 운영 화면 중심으로 간다.
- 표, 필터, 상태 배지 중심의 단순한 UI로 간다.
- 백엔드 API 시연이 목적이다.

예상 화면:
- 로그인 화면
- 관리자 주문 목록 화면
- 관리자 정산 목록 화면
- 발매/재고 조회 화면
- 주문/정산/발매 상세 확인 화면(필요 시 최소 수준)

---

### 4.4 시연 문서 / 시퀀스 다이어그램 보강
우선순위: 중

목표:
- DDIBS를 면접/포트폴리오 관점에서 더 설명 가능하게 만든다.
- 백엔드와 프론트 데모 흐름을 연결해 실제 시연 시나리오를 정리한다.

예상 작업:
- 주문 생성 / 홀드 / 결제 성공 시퀀스 다이어그램
- 홀드 만료 배치 시퀀스 다이어그램
- 정산 생성 배치 시퀀스 다이어그램
- 관리자 조회 흐름 정리
- 시연 스크립트 작성
- README / 리뷰 문서 보강

---

## 5. Out of Scope

아래 항목은 V3 범위에 넣지 않는다.

- 장바구니
- 쿠폰 / 포인트
- 리뷰 / 문의
- 배송 / 송장
- 환불 / 교환
- 외부 PG 실제 연동
- 사용자용 완성형 쇼핑몰 프론트
- 마이크로서비스 분리
- Kafka / MQ
- K8s
- 과도한 추천/통계/알림 기능

이 항목들은 DDIBS의 핵심 메시지를 흐릴 수 있으므로,  
최소 V3에서는 제외한다.

## 7. V3 완료 기준

V3는 아래 조건을 만족하면 마감으로 본다.

- 관리자 주문 조회뿐 아니라 **정산 조회와 발매/재고 조회**까지 운영 관점 기능이 연결된다.
- 최소 관리자 프론트엔드 데모 레이어가 동작한다.
- 백엔드 API와 프론트 데모가 시연 흐름으로 연결된다.
- 시퀀스 다이어그램과 시연 문서가 정리된다.
- DDIBS가 “고수요 발매 백엔드 시스템”이라는 메시지를 더 강하게 전달할 수 있다.

즉 V3는 새로운 커머스 기능을 많이 넣는 단계가 아니라,  
**운영 조회 · 최소 데모 프론트 · 시연 완성도**를 높여  
DDIBS를 더 보여주기 좋게 만드는 단계로 마감한다.

---

## 8. V4 예고

V3 이후 V4에서는 아래를 검토할 수 있다.

- 사용자용 발매 조회/주문/결제 흐름 프론트 추가
- 관리자/사용자 프론트 분리 구조 정리
- 데모 시나리오 확장
- 운영 관측 포인트 추가 고도화

단, V4에서도 중심은 여전히 백엔드이며,  
프론트엔드는 DDIBS 백엔드를 설명하기 위한 보조 수단으로 다룬다.

---

## 9. 한 줄 결론

DDIBS V3는 기능 추가 중심 단계가 아니라,  
**관리자 운영 조회 · 최소 프론트엔드 데모 · 시연 문서 완성도**를 높여  
DDIBS를 직접 보여줄 수 있는 운영형 백엔드 프로젝트로 끌어올리는 단계다.
