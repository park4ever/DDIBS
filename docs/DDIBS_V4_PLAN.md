# DDIBS V4 Plan

## 1. 문서 목적

이 문서는 DDIBS V4에서 무엇을 진행할지 정리한 계획 문서다.

V1이 **핵심 플로우 완성**,  
V2가 **테스트 재현성 / 배치 운영성 / 관리자 조회 고도화**,  
V3가 **운영 조회 확장 + 최소 프론트엔드 데모 레이어 + 시연 문서 정리** 단계였다면,

V4는 그 위에 **운영 조회 UX 완성도**와 **상세 조회 보강**을 더하는 단계로 정의한다.

즉 V4의 핵심은 새로운 범용 커머스 기능을 추가하는 것이 아니라,  
이미 완성된 DDIBS의 운영 흐름을 더 자연스럽고, 더 설명 가능하고, 더 시연하기 좋게 만드는 데 있다.

---

## 2. V4 목표

V4의 목표는 아래 4가지다.

1. **코드 검색 UX를 더 자연스럽게 리팩토링한다.**
2. **관리자 상세 조회를 보강해 운영 화면 완성도를 높인다.**
3. **프론트 운영 화면을 목록 중심에서 상세/탐색 중심으로 확장한다.**
4. **README 및 운영 문서를 V4 기준으로 다시 정리한다.**

정리하면 V4는  
“핵심 기능 추가”보다 **운영 조회 완성도 + 프론트 시연 UX 강화** 단계다.

---

## 3. V4 방향 요약

### V4에서 집중할 것
- 주문 / 정산 / 발매 코드 검색 정책 리팩토링
- 발매 상세 조회 완성
- 정산 상세 조회 완성
- 프론트 상세 화면 연결
- 운영 조회 UX polish
- README 및 문서 보강

### V4에서 지금 하지 않을 것
- 장바구니
- 쿠폰 / 포인트
- 배송 / 송장
- 환불 / 교환
- 실제 PG 연동
- 사용자용 풀 커머스 프론트
- 마이크로서비스 / Kafka / K8s

즉 V4도 여전히  
**DDIBS의 정체성을 강화하는 방향**으로 간다.

---

## 4. In Scope

## 4.1 코드 검색 정책 리팩토링
우선순위: 상

목표:
- 운영 조회에서 코드 검색 UX를 더 자연스럽게 만든다.
- exact match / partial match 정책을 일관성 있게 정리한다.

예상 작업:
- 주문 코드 부분 검색 지원 여부 결정
- 정산 코드 부분 검색 지원 여부 결정
- 발매 코드 부분 검색 지원 여부 결정
- QueryDSL 검색 조건 리팩토링
- 프론트 placeholder / 안내 문구 재정리

의도:
- 현재 exact match 위주 검색에서 오는 UX 아쉬움을 줄인다.
- 운영자가 코드를 일부만 기억해도 탐색 가능하도록 개선한다.

---

## 4.2 관리자 발매 상세 조회 보강
우선순위: 상

목표:
- DDIBS의 차별점이 가장 잘 드러나는 발매 / 재고 운영 상세를 강화한다.

예상 작업:
- 발매 상세 응답 구조 점검
- LaunchVariant 단위 재고 / 판매가 / 상태 표시 보강
- 프론트 발매 상세 화면 추가
- 발매 목록 → 발매 상세 진입 흐름 연결

의도:
- `LaunchVariant` 중심 재고 구조를 더 직접적으로 보여준다.
- DDIBS가 왜 일반 쇼핑몰이 아닌지 시각적으로 설명하기 쉬워진다.

---

## 4.3 관리자 정산 상세 조회 보강
우선순위: 중

목표:
- 정산을 단순 목록이 아니라, 운영자가 상세 추적 가능한 단위로 보여준다.

예상 작업:
- 정산 상세 응답 구조 점검
- 주문 코드 / 판매자 / 상태 / 금액 / 시각 정보 표시 정리
- 프론트 정산 상세 화면 추가
- 정산 목록 → 정산 상세 진입 흐름 연결

의도:
- 결제와 정산 생성을 분리한 설계를 더 잘 설명할 수 있게 한다.
- 운영자가 정산 상태를 더 구조적으로 파악할 수 있게 한다.

---

## 4.4 프론트 운영 조회 UX polish
우선순위: 중

목표:
- 현재 만든 관리자 프론트가 더 자연스럽고 읽기 쉬운 운영 화면이 되도록 다듬는다.

예상 작업:
- row 클릭 UX 개선
- 현재 필터 유지 여부 검토
- 코드 복사 UX 검토
- 날짜 필터 UX 정리
- 빈 결과 / 오류 메시지 polish
- 필요 시 가벼운 summary 표시 검토

의도:
- 화려한 UI가 아니라, 운영 화면으로서의 읽기 쉬움과 탐색성을 높인다.

---

## 4.5 문서 보강
우선순위: 중

목표:
- V4에서 추가한 운영 조회와 상세 화면을 README 및 문서에 반영한다.

예상 작업:
- README 보강
- V4 시연 포인트 정리
- 운영 화면 스크린샷 추가 여부 검토
- `DDIBS_V4_FINAL_REVIEW.md` 작성

의도:
- 구현과 문서의 간극을 줄인다.
- 포트폴리오 관점에서 전달력을 더 높인다.

---

## 5. Backlog / 후보 항목

아래는 기억해둘 만하지만, V4 핵심 범위에 바로 넣지는 않는 항목들이다.

### 5.1 사용자용 읽기 전용 프론트
후보:
- 발매 목록
- 발매 상세
- 품절 / 오픈 상태 표시

판단:
- 있으면 인상은 좋아질 수 있다.
- 그러나 V4 핵심은 아니며, 범위가 커질 수 있으므로 후순위로 둔다.

### 5.2 관리자 주문 상세
후보:
- 주문 상세 응답
- 주문 상태 / 결제 / 홀드 정보 연결

판단:
- 의미는 있지만, DDIBS 차별점 전달력은 발매 상세보다 낮으므로 후순위로 둔다.

### 5.3 검색 정책 세분화
후보:
- prefix match vs contains
- 대소문자 정책
- 코드 검색과 텍스트 검색 정책 분리

판단:
- V4 구현 중 자연스럽게 같이 정리할 수 있으나,
  과하게 복잡하게 만들지 않도록 주의한다.

- 장바구니
- 쿠폰 / 포인트
- 배송 / 송장
- 환불 / 교환
- 실제 PG 연동
- 사용자용 풀 커머스 프론트
- 마이크로서비스

즉 V4도  
**범용 쇼핑몰 기능 확대가 아니라, DDIBS 메시지를 더 강하게 만드는 단계**로 유지한다.

## 8. V4 완료 기준

V4는 아래 조건을 만족하면 마감으로 본다.

- 코드 검색 UX가 V3보다 자연스럽게 정리된다.
- 발매 상세 조회가 실제로 시연 가능하다.
- 정산 상세 조회가 실제로 시연 가능하다.
- 프론트 운영 조회가 목록 + 상세 흐름까지 연결된다.
- README 및 V4 리뷰 문서가 최신 상태를 반영한다.

즉 V4는 새로운 대형 기능 추가보다,
**운영 조회와 프론트 데모 완성도를 한 단계 더 올리는 것**을 목표로 한다.

---

## 9. 한 줄 결론

DDIBS V4는  
**코드 검색 리팩토링, 발매/정산 상세 조회, 운영 조회 UX polish**를 통해  
프로젝트를 더 자연스럽고, 더 시연 가능하고, 더 완성도 있게 만드는 단계다.
